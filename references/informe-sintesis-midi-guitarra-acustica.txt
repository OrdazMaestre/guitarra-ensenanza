Informe: Síntesis MIDI ligera de guitarra acústica
Resumen ejecutivo: Se propone crear un sintetizador de guitarra «de juguete» simplificado, con bajo polifonía (6 voces) y énfasis en notas abiertas y palm-mute. Usaremos AlphaTab con Node.js: cargaremos un SoundFont recortado o implementaremos síntesis Karplus-Strong por software. Se limitará la polifonía para evitar sobrecarga (por ejemplo, 6 voces máximas[1]) y activaremos mecanismos de voice-stealing (“note-cut”)[2]. Las envolventes ADSR serán cortas para simular el rápido decaimiento de guitarra y el palm-mute se modelará con una envolvente aún más breve y filtro pasobajo para atenuar graves. El flujo general pasa por: tabla de acordes → AlphaTab (MIDI) → sintetizador (SF2 o código) → filtro + envolvente → audio. Se deberán probar secciones con acordes largos (ej. 6 notas por compás) y perfilar CPU/latencia usando Chrome DevTools[3][4].

2. AlphaTab y carga de sintetizador
AlphaTab usa internamente un sintetizador MIDI + SoundFont[5]. Por defecto, al reproducir cargaría un banco general (por ejemplo, Sonivox). Para nuestro caso podemos:
Cargar un SoundFont minimalista: Usar Polyphone (editor SF2) para crear un .sf2 que contenga solo una muestra básica de guitarra acústica (por ejemplo, cuerdas al aire)[6]. Luego, en el código, cargarlo manualmente via:
const at = new alphaTab.AlphaTabApi(elem, { player: { enablePlayer: true } });at.scoreLoaded.on(score => {  score.tracks.forEach(track => {    if (track.playbackInfo.program === /*núm guitarra*/) {      // Cargar SoundFont recortado para guitarra      at.loadSoundFont(myGuitarSF2ArrayBuffer, true);    }  });});
Aquí usamos api.loadSoundFont(data, true) con true para agregar presets sin reemplazar[6].
Síntesis alternativa: En vez de SoundFont, podríamos interceptar cada evento de nota de alphaTab y disparar un sintetizador WebAudio/Tone.js personalizado. AlphaTab no provee directamente un API para síntesis manual por nota, pero se puede reproducir MIDI externo usando Tone.js. En este caso, el script de Copilot puede crear un PolySynth de 6 voces:
// Usando Tone.jsconst polyGuitar = new Tone.PolySynth(Tone.Synth, {  maxPolyphony: 6,  oscillator: { type: "triangle" },  envelope: { attack: 0.005, decay: 0.2, sustain: 0.2, release: 0.3 }}).toDestination();// Para palm-mute:const polyMuted = new Tone.PolySynth(Tone.Synth, {  maxPolyphony: 6,  oscillator: { type: "triangle" },  envelope: { attack: 0.005, decay: 0.05, sustain: 0.05, release: 0.1 }}).toDestination();
Este sintetizador de tonos simples (onda triangular) genera un timbre básico; las envolventes son rápidas para simular decaimiento breve.
Eventos AlphaTab: AlphaTab reconoce palm-mute solo como marcador visual[7], por lo que hay que detectarlo manualmente. Al procesar la tablatura, buscar notas con efecto Palm Mute, y para esas notas usar polyMuted.triggerAttackRelease(nota, duracion) en lugar de polyGuitar.triggerAttack.
3. Diseño del parche ligero de guitarra
Forma de onda y filtro: Se recomienda un oscilador simple (ej. triangular o diente de sierra) con un filtro pasobajo suave para quitar armónicos agudos. Como en guitarras reales, las frecuencias altas deben decaer más rápido[8], así que configuramos un lowpass (por ejemplo 1200–2000 Hz) para simular dicho decaimiento.
Envolvente ADSR: Notas abiertas con ataque muy rápido (<0.01 s), decay medio (~0.2 s), sustain bajo (~0.2) y release medio (~0.3 s) dan un sustenido breve. El palm-mute se modela igual pero acortando decay/release (ej. decay 0.05 s, release 0.1 s) y bajando el sustain al mínimo. Esto produce un sonido «apagado».
Velocity y articulación: Usar la velocidad de la nota para variar el brillo: notas más fuertes/agudas deben sonar “más brillantes”[9]. En Tone.js se puede lograr con filterEnvelope o keyTracking en el sintetizador.
Otros detalles: No agregamos efectos extra (reverb, chorus, vibrato) ya que buscamos un tono de juguete. Tampoco modelamos resonancia de caja o acople de cuerdas (estas aportan realismo pero encarecen el calculo). Lo esencial es un ataque claro, armónicos moderados y decaimiento rápido.
4. Polifonía y carga de acordes densos
Límite de voces: Configurar la polifonía máxima en 6 (una por cuerda)[1]. En Tone.js usamos PolySynth(6, ...), y en SoundFont configuramos synth.polyphony=6. Según docs, al pasar el límite se liberan automáticamente las voces menos recientes[1]. Esto evita desbordes de voz.
Voice-stealing (note-cut): Activar una política de “corte de nota” para que nuevas notas interrumpan a previas idénticas. En FluidSynth, synth.note-cut = 2 logra esto[2]. En código personalizado, podemos lanzar triggerRelease a la voz más antigua.
Cola de decaimiento corta: Reducir el release y sustain para que las notas mueran pronto, evitando acumulación de sonido. En entornos WebAudio, bajar el release en la envolvente (ej. 0.2 s) previene que voces antiguas consuman CPU tras la ejecución del acorde.
Ejemplo de limitación: Con Tone.js PolySynth(6), se garantiza un máximo de 6 osciladores. Si se toca un séptimo, Tone reasigna internamente (voice-stealing) en orden FIFO. Para SoundFont, asegúrese de que el engine (synth.polyphony) esté a 6.
Filtro adicional: Si aún hay problemas, considere simplificar la onda (seno) o bajar la tasa de muestreo (aunque en WebAudio estándar es 44.1 kHz por defecto). Un trazo extremo es muestrear a 22050 Hz, pero esto generalmente lo hace el buffer del SoundFont. En síntesis, controlar la calidad de la señal para bajar CPU.
5. Palm Mute
Marcador en AlphaTab: AlphaTab muestra “Palm Mute” en la partitura[7], pero no modifica el sonido automáticamente. Debemos usar esa información: al detectar un nodo con palm-mute, desencadenar la versión «apagada» de la voz (volver a ejecutar la nota con polyMuted en Tone.js o aplicar filtros/envolvente en SoundFont).
Implementación en código: Por ejemplo, al procesar la pista:
at.player.playing.on(p => {  // Suponiendo que p.note.effects contiene palm-mute  if (p.note.effects && p.note.effects.some(e => e.name === "PalmMute")) {    polyMuted.triggerAttackRelease(p.note.fractionalMidi, p.duration, p.velocity);  } else {    polyGuitar.triggerAttackRelease(p.note.fractionalMidi, p.duration, p.velocity);  }});
Este pseudocódigo (basado en la API de eventos de alphaTab) asigna a palm-mute la voz rápida y apagada.
Ajustes de ecualización: El palm-mute típicamente elimina bajos y medios graves. Un filtro pasaalto suavizado (e.g. cortar por debajo 100-150 Hz) puede evitar sonido «embarrado» en palm-mute. Opcionalmente, un leve boost medio (500–1000 Hz) enfatiza el golpe. Sin embargo, como buscamos simplicidad, con la envolvente reducida suele ser suficiente.

Sólido para un sonido de juguete. Karplus-Strong simula cuerda punteada[11] con parámetros ajustables.
Palm Mute

Fácil: modificar envolvente y filtro en tiempo real (como se hizo). Más flexible.
Polifonía
Controlada por el synth (FluidSynth, etc.). Podemos fijar polyphony=6[1].

Personalización
Limitada: editar el SF2 es menos práctico.
Alta: parámetros de filtro, Q, ruido, ataque, etc. fácilmente modificables.
7. Pruebas y optimización
Casos de prueba: Crear un script o usar AlphaTab para reproducir acordes densos (ej. Ce4,Gc,Ad,Fd,Bd,Ed durante 8 compases). Verificar sonido continuo.
Perfilado en Chrome/Electron: Abrir DevTools → pestaña Performance (o Memory/CPU). Reproducir los acordes y buscar picos de CPU o caídas de frames[3]. Ajustar parámetros según resultado.
Métricas: Medir uso de CPU durante reproducción (debe mantenerse moderado). Observar audio dropouts (ausencia indica sobrecarga). Comprobar latencia: AlphaTab advierte que hay latencia de audio dependiente de la máquina[4]. Usar un metrónomo interno para medir delay.
Comparación de modos: Probar tanto la versión SoundFont como la de síntesis programática. Medir diferencias de recursos y calidad. Ajustar el volumen general para uniformidad.
Ajustes finales: Si aparecen clicks o recortes abruptos, suavizar envolventes. Si CPU sigue alta, reducir polyphony (p.ej. 4 voces) o simplificar onda (onda seno, menos filtros activos).
